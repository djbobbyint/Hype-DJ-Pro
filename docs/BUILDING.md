# Building HYPE DJ PRO

Dependencies are fetched by CMake: JUCE 8.0.4 (or a checkout in `external/JUCE`), Signalsmith Stretch 1.4.0.

## Linux (tested: Ubuntu 24.04)
```bash
sudo apt install build-essential cmake ninja-build libasound2-dev libfreetype-dev libfontconfig1-dev \
     libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev \
     libavformat-dev libavcodec-dev libswresample-dev libavutil-dev    # FFmpeg: optional, for AAC/M4A
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/hype_phase1_tests && ./build/hype_engine_tests
"./build/HypeDJPro_artefacts/Release/HYPE DJ PRO"
```

## Windows x64: cross-built from Linux (how the delivered build was made)
```bash
scripts/build-windows.sh            # → build-win/HYPE-DJ-PRO-windows-x64.zip and HYPE-DJ-PRO-<version>-Setup.exe
```
This uses the distribution's Clang 18, targeting `x86_64-w64-windows-gnu` with the mingw-w64 sysroot
(`cmake/clang-mingw-w64-x86_64.cmake`). JUCE 8 officially targets MSVC, so the build adds:
- a few newer mingw-w64 headers (Direct2D 1.3, UI Automation), generated by the script into a compat include
  directory (`HYPE_MINGW_COMPAT_INCLUDE`);
- `cmake/mingw/HypeMingwCompat.cpp`: two `__uuidof` specialisations, the Speech API class id, and a
  `_get_tzname` shim for the MSVCRT runtime;
- a Windows 10 target (`_WIN32_WINNT=0x0A00`), an explicit system-library list, and static GCC/C++ runtimes.

FFmpeg is built from source (LGPL, audio-only, shared DLLs with no extra runtime dependencies).
The installer is a native 64-bit NSIS installer (`packaging/windows/installer.nsi`): Program Files, all-users
Start-menu and optional desktop shortcuts, optional test suites, and an uninstaller registered in Apps & features.
The resulting executables import only Windows system DLLs plus the four FFmpeg DLLs.

## Windows x64: native with Visual Studio 2022 (not yet built or tested here)
JUCE's primary Windows toolchain, and the right choice for production builds:
```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DHYPE_FFMPEG_ROOT=C:\path\to\ffmpeg-lgpl-shared
cmake --build build --config Release
```
`HYPE_FFMPEG_ROOT` must contain `include\`, `lib\` (import libraries) and `bin\` (DLLs), for example an LGPL shared
build of FFmpeg 6.x. Without it, AAC/M4A won't load (WAV/AIFF/FLAC/Ogg/MP3 still work).

### ASIO
Download the Steinberg ASIO SDK (it can't be redistributed) and add `-DHYPE_ASIO_SDK_DIR=C:\path\to\asiosdk`.
ASIO then appears as a driver type in Audio Settings.

## macOS (not yet built or tested)
```bash
cmake -S . -B build -G Xcode && cmake --build build --config Release
```
CoreAudio provides devices and AAC/M4A decoding; FFmpeg is optional.
